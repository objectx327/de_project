# Неделя 6. Данные к домашнему заданию

Синтетические данные NordMarket. Архив дополняет PDF «Неделя 6. ETL и ELT» и заменяет ручное создание исходных файлов по его таблицам. Логику загрузки, DDL и проверки Вы реализуете самостоятельно.

## Формат

orders.jsonl: UTF-8 без BOM, один JSON-объект на строку. Пустые наборы представлены файлами размером 0 байт. amount является строкой с точкой, для удаления amount и status равны JSON null. Идентификаторы остаются строками. Все даты: 29.09.2026, UTC, явное смещение +00:00. Ключ: source_system + order_id.

Поля записей: source_system, order_id, source_version, operation, status, amount, updated_at, available_at. Во всех upsert валюта EUR. Ведущие нули сохраняются. Не используйте float для сумм.

Для одинаковой версии сравниваются operation, status, amount. updated_at и available_at нужны для извлечения, а не для определения равенства бизнес-состояния. Например, pos/000001 приходит повторно с другим updated_at. Это разрешённый повтор той же версии.

manifest.json описывает поставку. data_file задан относительно папки манифеста; record_count считает логические записи, sha256 проверяет неизменность байтов файла. complete=true подтверждает полноту указанной поставки в её scope на as_of. Это не обещание отсутствия будущих запоздавших изменений. Отсутствие complete не равно true: такой полный снимок нельзя публиковать. Нулевая длина файла и совпадение record_count сами по себе не подтверждают полноту.

scope относится к исходным системам shop и pos. mode=full означает полный снимок, delta означает изменения, replay означает отдельную проверку повторного применения без продвижения watermark. Служебные поля манифеста не добавляйте в JSON каждой исходной строки; batch_id и run_id можно присоединять при загрузке staging.

## Основные данные

raw/full_0800: 4 строки полного снимка на 08:00. Начальная граница прогресса после публикации: 08:00.

raw/delta_1: 7 строк для (08:00; 09:00]. Повтор строки shop/000004 сохранён намеренно, порядок исходных строк менять не нужно.

raw/delta_2: 4 дополнительные строки источника, доступные на 10:00. Это НЕ готовая выборка для (09:00; 10:00]. Строка shop/000005 имеет updated_at=08:55, available_at=09:05. У этого файла нет собственного lower_bound: отбор предстоит реализовать Вам.

Для задания 4 объедините записи raw/delta_1/orders.jsonl и raw/delta_2/orders.jsonl. Отберите доступные на as_of=10:00 строки по available_at, затем по updated_at. Без перекрытия: updated_at > 09:00 и <= 10:00. С перекрытием: updated_at >= 08:45 и <= 10:00. Сохраняйте порядок и повторы исходного набора до этапа подготовки. Манифест полученной выборки сформируйте сами: lower_bound=09:00 (watermark), upper_bound=10:00; фактическое начало чтения 08:45 фиксируется отдельно. Данные full_0800 в журнал изменений не добавляются.

reference/full_1000: 5 строк полного активного состояния для независимого пути сверки в задании 6. Это источник для отдельной тестовой таблицы, а не подмена реализации дельты. updated_at сохранён по последним строкам источника, поэтому он может быть раньше времени снимка 10:00. Состояний удаления здесь нет.

## Проверочные файлы

fixtures/initial_target.jsonl: необязательная заготовка исходной цели перед full load: shop/000001 на 90.00, лишний shop/X на 5.00 и partner/000001 на 999.00. Значения 90.00 и 5.00 уточняют произвольные начальные значения из PDF. is_deleted=false во всех трёх строках. Это тестовое состояние цели, не поставка источника и не начальный watermark; технические поля цели задайте при подготовке.

fixtures/conflict_1015: 4 строки из задания 4, включая конфликт версии 3, более новую версию 4 и новый заказ 000007. Пакет блокируется целиком.

fixtures/conflict_target_1015: 1 строка shop/000004, версия 2, paid, 46.00. Противоречит сохранённой версии 2 с суммой 45.00. Запускается отдельной попыткой после получения состояния на 10:00.

fixtures/empty_full_confirmed: 0 строк, complete=true. Проверяется на отдельной копии исходной цели.

fixtures/empty_full_unconfirmed: 0 строк, поле complete отсутствует. Публикация запрещена.

fixtures/empty_delta_1000_1100: 0 строк подтверждённой дельты (10:00; 11:00]. Состояние сохраняется, прогресс может продвинуться. Используйте после проверки конфликтных поставок, как отдельную поставку основного потока.

fixtures/replay_old_000001: 1 строка старой версии shop/000001. Проверяется после delta_1; watermark не продвигается.

fixtures/replay_delete_000006: 1 повтор удаления shop/000006 версии 2. Проверяется после рабочего запуска до 10:00; watermark не продвигается.

Конфликтные и replay-пакеты не добавляются в основной журнал raw/delta_1 + raw/delta_2. Для полного повтора delta_1 используйте исходный batch_id=delta_1 и новый run_id. Не создавайте новые версии записей ради повторного запуска.

## Сбои и контроль

Для обоих воспроизводимых сбоев задания 5 используется обычная delta_1, отдельного повреждённого файла не нужно. Исключение добавляется в загрузчик в требуемой точке. Каждый сценарий начинается с full_0800 и watermark=08:00 на отдельной копии.

Все проверки количества и суммы относятся только к shop и pos. Контроль после full_0800: 4 активных заказа, 420.00 EUR. Итог на 10:00: 5 активных заказов, 315.00 EUR и 2 состояния удаления. partner/000001 остаётся на 999.00 EUR и не входит в эти суммы. cancelled считается активным, то есть неудалённым, заказом.

Файлы не содержат готового загрузчика и решений заданий. Повторные строки, старые версии, события удаления и конфликтные состояния являются намеренными данными сценариев: не исправляйте их вручную.
