# Неделя 5. API и внешние источники

Учебный кейс: интернет-магазин «СеверМаркет» получает заказы из вымышленной системы NorthCart. Все данные синтетические.

В архиве есть готовый локальный HTTP API, два состояния источника, SQL для учебных таблиц и задание в PDF. Написать нужно **клиентский загрузчик**. Сервер изменять не требуется. Данные для загрузки получайте через HTTP, а не чтением JSON из папки `data`.

## Файлы

| Файл | Назначение |

| `DE_Week5_Homework.pdf` | Восемь связанных заданий и контрольные результаты |

## Запуск: macOS / Linux

Откройте терминал в распакованной папке. Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export DE5_API_TOKEN='training-only'
.venv/bin/python server.py
```

## Запуск: Windows, PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DE5_API_TOKEN = 'training-only'
.\.venv\Scripts\python.exe server.py
```

`training-only` - открытое учебное значение, а не ключ реального сервиса. Сервер берёт ожидаемое значение из окружения. Загрузчик должен получать такое же значение из окружения своего терминала, не из строки в коде. Настройка переменной в одном терминале не настраивает другой терминал.

Оставьте сервер работающим. Откройте `http://127.0.0.1:8765/health` в браузере: ожидается `{"status": "ok"}`. Запрос к `/v1/orders` требует заголовка авторизации, поэтому открытие этой страницы в браузере без заголовка вернёт 401.

Остановка: Ctrl+C. Повторный запуск сервера сбрасывает счётчики временных ошибок. Если порт занят, используйте `server.py --port 8766` и измените базовый адрес в загрузчике. Сервер слушает только `127.0.0.1` и предназначен для локальной практики; HTTP здесь используется внутри компьютера.

## PostgreSQL и терминал загрузчика

Откройте `setup.sql` в SQL-клиенте и выполните его **в своей учебной базе**. Создавать другую базу или менять таблицы прошлых недель не нужно. Скрипт не удаляет данные. `orders` и `order_items` в схеме `de5_hw` выполняют роль staging текущего состояния.

В другом терминале задайте `DE5_API_TOKEN`, а также параметры своей базы `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`. Например, для macOS/Linux:

```bash
export DE5_API_TOKEN='training-only'
export PGHOST='localhost'
export PGPORT='5432'
export PGDATABASE='имя_учебной_базы'
export PGUSER='учебный_пользователь'
```

В PowerShell те же имена задаются как `$env:PGHOST = 'localhost'`. Пароль задайте в окружении локально; не записывайте его в README, исходный код или Git. Не печатайте параметры подключения целиком. Значения базы и пользователя выше замените на свои.

Запускайте свой загрузчик интерпретатором из `.venv`: `.venv/bin/python` на macOS/Linux или `.\.venv\Scripts\python.exe` в PowerShell. Необходимые зависимости перечислены в `requirements.txt`; серверу сторонние библиотеки не нужны. Диапазоны версий в этом файле не являются фиксацией точной версии окружения.

## Последовательность практики

1. Выполните задания 1-4 из PDF с `snapshot=initial`, `scenario=normal`, `limit=4` и периодом `[2026-09-24T00:00:00Z, 2026-09-27T00:00:00Z)`.
2. Повторите тот же запуск, затем выполните задание 5 с `snapshot=updated` и периодом `[2026-09-26T00:00:00Z, 2026-09-28T00:00:00Z)`.
3. Выполните сценарии заданий 6-7. Перед каждым независимым тестом восстановите известное состояние только учебной схемы `de5_hw` либо используйте отдельную учебную базу. Запишите, с какого состояния начат тест. Сброс PostgreSQL сам по себе не сбрасывает состояние сервера.
4. Проверьте счётчики и оформление команд своего загрузчика по заданию 8.

Для сценария `timeout_once` задайте read timeout 0.2 секунды: первый ответ второй страницы задерживается на 1 секунду. Для остальных сценариев подходит `(2, 5)`. Перед повторной проверкой сценария с разовой ошибкой перезапустите сервер.

Снимок `updated` фиксирован на весь тест. Это позволяет сравнивать результаты. У реального API стабильность выборки и срок действия курсора проверяют отдельно по документации.
